# 스크롤로 조절하는 3D 모션

2026-10-19. 평면 이미지의 확대·이동 연출을 여러 부품으로 구성한 Three.js 장면으로 교체했다. 동영상을 자동 재생하거나 토스의 영상·브랜드 에셋을 복제하지 않는다. 각 물체의 위치·회전·투명도를 스크롤 진행률로 계산하므로 스크롤을 멈추면 자세를 유지하고 역방향에서도 같은 상태를 복원한다.

## 구성

| 장면 | 개별 Mesh 수 | 움직임 |
| --- | ---: | --- |
| 디지털 포렌식 | 162 | 나사를 뽑아 왼쪽으로 이동 → 덮개 열림 → 플래터·헤드 암 노출 → 돋보기가 오른쪽 아래에서 진입 |
| Android 보안 | 111 | 평면 화면 분리 → 칩 상승 → 로봇 반응. 반투명 필름은 모델에서 완전 삭제 |
| 리버스 엔지니어링 | 151 | 금속 덮개 상승 → 유리·다이·패키지 분리 → 내부 타일 전개 |

| Web3 보안 | 96 | 연결된 블록 → 가운데 덮개 상승 → 계약 카드·저장 슬롯 전개 |
| 퍼징 | 89 | 분석 장치 양쪽 덮개 분리 → 입력·데이터 변형 → 황색 오류 후보 분리 |

선과 그룹은 Mesh 수에 포함하지 않는다. 부품 수는 브라우저에서 실제 모델 트리를 순회해 확인했다. 물체는 재질·광원·반사·그림자를 갖는 코드 기반 모델이다.

## 동작과 파일

- `components/InterestScenes.jsx`: sticky 영역의 스크롤 진행률, 현재 장면 표시, 프로젝트 링크.
- `components/SceneCanvas.jsx`: 가까운 장면의 지연 로딩, 마우스 입력, 정적 대체 이미지.
- `components/interest-3d-runtime.js`: 카메라, 조명, 그림자, 렌더링·자원 해제, Raycaster를 통한 부품 감지.
- `components/interest-models.js`: 다섯 물체의 부품과 진행률별 위치·회전.
- `lib/scene-motion.mjs`: 0~1440의 자세 번호와 부품별 이동 경로, 단계별 smoothstep 곡선. 자동 재생은 없으며 실제 표시 속도는 화면의 requestAnimationFrame 주기에 따른다.
- `tests/scene-motion.test.mjs`: 정·역방향 동일 자세 복원, 정지, 단계 순서, 입력 범위 검증.
- `tests/scene-geometry.test.mjs`: 전체 1,441개 자세에서 실제 Three.js geometry의 경계 검사. 스마트폰에 투과 재질 부품이 전혀 없는지, 열린 덮개와 나사, 들어오는 돋보기와 회로판, Web3 덮개와 계약, 퍼징 오류 후보와 덮개의 교차를 검사한다. 회전된 world AABB가 빈 공간을 포함하는 오탐을 피하도록 폰 기준 좌표에서 검사한다.
- `components/studio-surfaces.js`: 브러시드 메탈 거칠기, 대리석 바닥과 부드러운 그림자, 평면 Android 화면을 CanvasTexture로 생성한다. 외부 사진을 배경으로 붙인 것이 아니다.
- `lib/scene-studies.js`: 부품에 연결할 짧은 학습 기록과 기존 상세·블로그 링크.

마우스는 장면 전체를 작게 기울인다. Raycaster로 가리킨 부품을 감지해 점선 경계·연결선·작은 학습 카드를 표시한다. 부품을 확대하여 다른 부품을 침범하던 동작은 제거했다. 터치는 스크롤을 가로채지 않으며 학습 기록 버튼으로 같은 설명을 연다. 링크 포커스 중 카드를 유지하고 Escape로 닫는다.

렌더 해상도는 모바일 DPR 1.5, 데스크톱 DPR 2로 제한한다. 그림자 해상도도 화면 크기에 따라 1024/2048로 나눈다. 화면 밖·숨겨진 탭에서는 GPU 렌더링을 건너뛰고, 화면 안에서도 자세·포인터·화면 크기가 같으면 다시 그리지 않는다. 해제 시 geometry, material, 모든 material texture, WebGL context와 observer를 정리한다. WebGL 초기화 실패 시 기존 컨셉 이미지가 남는다. 동작 줄이기에서는 기울기와 스크롤 재생을 생략하지만 학습 기록은 열 수 있다.

Android UI는 단일 평면 텍스처이며 화면 위에 구체를 올리지 않는다. 투명 필름 세 장과 해당 이동·표시 코드를 완전히 삭제했다. 모바일 로봇은 아래쪽의 별도 공간에 배치한다.

Auth.js, MongoDB, 관리자 동기화, Vercel Cron, 아카이브 데이터는 변경하지 않았다.

사용자가 승인한 A(Web3)·B(퍼징)는 제안용 정적 이미지를 영상처럼 이동시키는 방식이 아니라 독립 Mesh로 구현했다. Web3는 Ethernaut, 퍼징은 Fuzzing101 기존 블로그 기록과 연결한다. 새 분야는 홈 관심 장면만 추가하고 진행 프로젝트 여섯 항목은 유지한다. 새 장면의 WebGL 대체 이미지는 로컬 SVG다.

## 광학 스튜디오 재제작

다섯 모델 모두 미세 가공 디테일을 추가했다. 저장장치는 뚜껑 가공선·기판 부품·칩 마킹·렌즈 링, 스마트폰은 밀링 버튼·스피커·카메라·테두리, 프로세서는 본딩 와이어·체결 나사·덮개 가공선을 갖는다. 반복되는 작은 회로 부품 48개는 InstancedMesh로 묶었다.

Web3와 퍼징의 기존 단순 상자 구조를 속이 빈 광학 하우징으로 다시 제작했다. 유리는 alpha .32로 희석하지 않고 opacity 1, transmission, IOR, thickness, attenuation으로 표현한다. 연결축과 플랜지·검은 실링·볼트·가공 핀·출력부를 별도 부품으로 구성한다. 투명층을 제거한 Android는 투과 재질 부품이 없다.

렌더러는 AgX 톤 매핑, HDRI 스튜디오 환경, VSM 그림자, 평면 반사와 연속 곡면 배경을 사용한다. 바닥은 대리석 재질의 줄눈 없는 내부 구간만 UV로 사용한다. 반사 버퍼는 데스크톱 768/모바일 384로 제한한다. HDR·텍스처 로드는 비동기이며 완료 시 정지 중인 장면도 다시 그린다. 언마운트 이후 도착한 자원과 HDR PMREM·반사 타깃을 해제한다. HDR 실패 시 기존 스튜디오 환경을 유지한다.

광원과 석재 원본은 Poly Haven CC0이며 출처·저자·파일 해시는 `studio-assets.json`에 기록한다. 로컬 파일로 제공하므로 방문자가 제3자 도메인에서 텍스처를 불러오지 않는다. 이 실시간 WebGL 렌더는 제안 이미지의 오프라인 광선 추적 결과와 같은 렌더 방식은 아니다. 이미지에 맞춘 재질·구조·구도를 실제 브라우저에서 검증한다.

## 조립·호버·퍼징 후보 수정

- 퍼징 후보는 18개 코퍼스 큐브 중 하나로 처음부터 존재한다. 원래 위치에서 색이 청색→황색으로 바뀌고 크기가 연속적으로 커지며 위로 빠져나온 뒤 오른쪽으로 이동한다. 작은 후보의 화면 공간 굴절이 금속 덮개를 샘플링해 깨져 보이던 문제를 피하도록 후보만 투과 없는 광택 코팅 재질을 사용한다. 하우징의 물리 유리는 유지한다.
- 포렌식 덮개 네 나사 자리는 실제 ExtrudeGeometry의 관통 구멍과 원뿔형 카운터싱크다. 나사 머리 반경 .075, 구멍 입구 .064, 줄기 .028, 관통부 .034로 서로 맞춘다. 네 자리 모두 레이캐스트로 관통과 주변 금속을 검사한다.
- Android는 앞쪽 테두리 프레임을 추가해 내부 회로를 감싸고 초기 화면 z를 .38로 조정했다. 닫힌 화면 가장자리는 프레임과 맞물리고 칩과는 간섭하지 않는다. 분해는 기존 open 단계에서 시작한다.
- 부품을 벗어나도 마지막 학습 카드가 유지된다. 다른 부품으로 변경하거나 ×·Escape·학습 기록 버튼으로 닫을 수 있다. `lib/study-selection.mjs`는 빈 공간을 지나 링크까지 이동하는 유지/닫기 정책을 처리한다.

## HDD 및 슬림 Android 내부 재구성

포렌식 장면은 회로판을 기계식 HDD의 내부로 교체했다. 두 플래터, 스핀들·클램프와 체결 나사, 타공된 헤드 암·피벗·헤드 팁, 구리 보이스코일, 재순환 필터, 플렉스 연결부와 SATA 접점을 모델링했다. 제어 기판은 하부에 배치했다. 플래터와 헤드 암의 움직임은 스크롤 scan 단계에 연결되며, 자동 회전은 없다. 나사 체결부 네 곳은 덮개와 같은 XY 좌표의 원통형 보스다. 실제 관통부 반경 .034와 나사산을 두어 작은 구멍이 본체에도 남는다.

Android는 전면 화면·중앙 프레임·후면 케이스를 새 깊이로 재구성했다. 닫힌 본체 폭 1.808, 두께 .182(약 10.1%)로 이전 약 .55 두께의 3분의 1 수준이다. 특정 제품의 실측 치수가 아닌 모델 비율이다. 상단 메인보드와 BGA SoC·메모리, EMI 실드, 카메라 모듈, 중앙 배터리 파우치, 하단 충전 보드·USB-C·스피커·진동 모터를 구분했다. 작은 표면실장 부품을 InstancedMesh로 묶고 리본 케이블·커넥터·배터리 풀탭을 추가했다. 후면 카메라 배럴은 화면이 아닌 후면을 향하며 후면 케이스에도 대응하는 개구부를 냈다. 실드는 화면을 연 뒤 옆으로 분리되어 SoC를 드러낸다.

참고 자료는 [Seagate M8 제품 매뉴얼의 HDA·전자부 구성](https://www.seagate.com/www-content/support-content/samsung/internal-products/spinpoint-m-series/en-us/100698035j.pdf), [iFixit Pixel 9 Pro XL Chip ID](https://www.ifixit.com/Teardown/Google+Pixel+9+Pro+XL+Chip+ID/176196), [Pixel 9 Pro 배터리 분해 안내](https://www.ifixit.com/Guide/Google+Pixel+9+Pro+Battery+Replacement/176343)다. 사진이나 도면을 복제한 특정 제품 CAD가 아니라 구성과 배치를 참고해 코드로 만든 설명용 모델이다.

검증은 1,441개 스크롤 자세의 간섭/역방향 복원, 덮개 구멍과 하부 보스의 축 정렬·실제 개구부, 닫힌 폰의 두께 비율과 프레임 접촉, 배터리와 상하부 기판의 분리를 포함한다.
